Official PayPal US guidance separates account creation from linking a card in Wallet. No public consumer-wallet GraphQL operation for the private phone-login/add-card UI was found, so the adapter uses PayPal's official member page for those private UI steps and then verifies the resulting protocol state.

MVP/Strategy design
-------------------
Model: paypal/us_email_first.py stores email, phone-verification, buyer, EUAT, funding and ordered-event facts.
Presenter: UsEmailFirstPresenter enforces create_email_account -> request_phone_otp -> confirm_phone_otp -> hydrate_authenticated_buyer -> bind_card -> authorize.
Strategy: EmailFirstAuthorizationStrategy gates every downstream step and retries only authenticated card binding.
View: PayPalFlow owns protocol orchestration; WebPayPalFlow owns deferred phone acquisition, official-page member login/card binding, private autofill and automatic OTP bridging.

Protocol gates
--------------
1. A bootstrap EC no longer counts as the US email step. Phase 2 must run Pay_With_Card and Continue_To_Payment with _1_login_email.
2. The email request contains no phone/card field and must return a successful action redirect, onboarding URL or explicit EC token.
3. Automatic US phone acquisition happens only after email_submitted=true.
4. US Phase 3 does not call the legacy combined SignUpNewMember path.
5. Browser completion rejects /checkoutweb/signup and /signin; it accepts only an authenticated PayPal review route with EUAT.
6. authorize requires buyer userId, EUAT and selected fundingOptions.fundingInstrument.id. allPlans-only availability is insufficient.
7. IdentityElevation preserves an already authenticated US member/funding context and skips destructive signup re-entry.
8. Non-US countries retain the legacy OTP + SignUpNewMember order.
